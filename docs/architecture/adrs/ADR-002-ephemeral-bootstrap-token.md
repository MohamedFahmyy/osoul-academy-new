# ADR-002: Ephemeral Bootstrap Token

## Status
Accepted

## Context
When launching the secure desktop client via a deep link protocol (`asap://open?url=...`), the browser must pass a credential allowing the desktop client to securely download the session keys. If this credential is static or long-lived, it risks interception (e.g. by malware monitoring deep-link registrations or process arguments).

## Decision
We implement a hashed, single-use, short-lived **Ephemeral Bootstrap Token**. 
- The token is a secure random 32-character string generated by the server.
- The server stores the SHA-256 hash of the token (`bootstrap_token`) and a strict 2-minute expiration timestamp (`bootstrap_token_expires_at`).
- During the Electron client's handshake request, the client sends this token. The server verifies the SHA-256 hash, checks expiration, decrypts the session key, and immediately consumes the token by setting the database fields to `null`.

## Key Cryptography Contract
- **Bootstrap Token**: Plaintext secure random string passed via deep-link protocol, hashed in DB.
- **Session Key**: Random AES-256 key generated per-session, encrypted with application key, and transferred during handshake.
- **Lifetime**: 2-minute expiration for the bootstrap token; up to 4 hours for the session key.

## Consequences
- The token cannot be reused (replay attacks are prevented).
- Even if the database is compromised in read-only mode, the hashed tokens cannot be used to bootstrap active sessions.
