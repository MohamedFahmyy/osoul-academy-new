# ASAP Specification Sheets
## AT Loops Secure Assessment Platform (ASAP)

This document contains the foundational contract rules, classifications, and codes for the ASAP domain.

---

## 1. Event Catalog

All security events generated by the client and sent to the server MUST use one of the following unified event codes:

| Event Code | Category | Severity | Description |
| :--- | :--- | :--- | :--- |
| `WINDOW_UNFOCUS` | `WINDOW` | `WARNING` | Client window lost focus (e.g., student clicked away). |
| `WINDOW_FOCUS` | `WINDOW` | `INFO` | Client window regained focus. |
| `DISPLAY_ADDED` | `DEVICE` | `CRITICAL` | A secondary display or monitor was connected. |
| `DISPLAY_REMOVED` | `DEVICE` | `INFO` | A secondary display or monitor was disconnected. |
| `PROCESS_BLACKLIST_DETECTED` | `PROCESS` | `CRITICAL` | A blacklisted software process (e.g., OBS, Discord) was detected running. |
| `HEARTBEAT_TIMEOUT` | `SYSTEM` | `CRITICAL` | Server failed to receive heartbeats from client within threshold. |
| `CLIENT_DISCONNECTED` | `NETWORK` | `CRITICAL` | Client lost network connectivity to the server. |
| `FULLSCREEN_EXIT` | `WINDOW` | `CRITICAL` | Client window exited fullscreen mode. |
| `DEVTOOLS_DETECTED` | `WINDOW` | `CRITICAL` | Browser developer tools opening was detected. |
| `VM_DETECTED` | `SYSTEM` | `WARNING` | Client running inside a Virtual Machine was detected. |
| `NETWORK_LOST` | `NETWORK` | `WARNING` | The client detected a local gateway drop or DNS failure. |

---

## 2. Policy Matrix

The Default Policy defines weights, cooldowns, and actions for events. These thresholds are parsed dynamically by the Policy Engine:

* **Warning Threshold:** `40`
* **Pause Threshold:** `60`
* **Terminate Threshold:** `85`

| Event Code | Default Weight | Cooldown Window | Default Action |
| :--- | :---: | :---: | :--- |
| `WINDOW_UNFOCUS` | `10` | 30 seconds | `WARN` |
| `FULLSCREEN_EXIT` | `20` | 30 seconds | `WARN` |
| `DISPLAY_ADDED` | `30` | 0 seconds | `PAUSE` |
| `PROCESS_BLACKLIST_DETECTED` | `60` | 0 seconds | `PAUSE` / `TERMINATE` |
| `HEARTBEAT_TIMEOUT` | `40` | 0 seconds | `PAUSE` |
| `DEVTOOLS_DETECTED` | `50` | 0 seconds | `PAUSE` |
| `VM_DETECTED` | `15` | 0 seconds | `WARN` (Risk addition only) |

## 3. API Error Codes

To maintain a robust integration with Electron and other secure clients, ASAP APIs return structured error codes instead of generic messages:

| Error Code | HTTP Status | Short Message | Detailed Description |
| :--- | :---: | :--- | :--- |
| `ASAP-1001` | `401` | `Invalid Session` | The session key is expired, invalid, or does not exist. |
| `ASAP-1002` | `403` | `Device Not Trusted` | The device is suspended, revoked, or pending approval. |
| `ASAP-1003` | `408` | `Heartbeat Timeout` | Heartbeat not received within the required window. |
| `ASAP-1004` | `400` | `Invalid Signature` | Request HMAC signature check failed (tampering suspect). |
| `ASAP-1005` | `403` | `Policy Violation` | Risk score threshold exceeded or forbidden action taken. |
| `ASAP-1006` | `426` | `Client Version Unsupported` | The client version is outdated and must be updated. |
| `ASAP-1007` | `409` | `Session Already Active` | An active session already exists on another client for this user. |
